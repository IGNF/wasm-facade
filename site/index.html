wasm-facade Overview Demo Reference

Declare the API once, in Rust. Generate the rest.

wasm-facade reads inert attributes on a crate compiled with wasm-bindgen and writes what a JavaScript user calls: a TypeScript facade, React hooks, a reference, and any target a plugin adds.

orval, for Rust and wasm

orval writes a typed client from an OpenAPI document, so the client never drifts from the contract. wasm-facade does the same, with the Rust crate as the contract.

orval openapi.json the document client, React Query hooks, mocks
wasm-facade the Rust crate api.json, with its schema facade, React hooks, reference, plugins

What wasm-bindgen writes

new Blur(radius: number, edge: Edge)   // Edge = 0 | 1
blur.onProgress(listener: Function)
blur.apply(image: Uint8Array, w, h)
blur.free()                            // to remember

What wasm-facade adds on top

new Blur({ radius: 4, edge: 'wrap' })  // defaults filled
const stop = blur.on('progress', (share) => …)
blur.apply(imageData, w, h)            // your converter
useBlur(options)                       // freed on unmount

In a repository

  1. Declare in Rust

    The attribute sits behind a cfg that is never set: no proc-macro, no dependency, no build time.

    #[cfg_attr(wasm_facade,
  api(class, options = "BlurOptions"))]
#[wasm_bindgen]
impl Blur { … }

  2. Pick the targets

    One file at the root says what to write and where.

    # wasm-facade.toml
wasm = "../pkg/filters.js"
[targets.typescript]
[targets.react]
[targets.reference]

  3. Generate, check in CI

    After a change to the Rust, and in the lint, which fails on any drift.

    $ wasm-facade generate
$ wasm-facade check
